# 검수 초기화 및 JSON 병합 불러오기

## 목적과 기준

PRD 13·14절 및 검수 JSON·브라우저 저장 규칙을 따른다. 사용자 승인에 따라 화면에서 전체 검수를 초기화하고 JSON 불러오기 시 파일에 없는 공명자를 유지한다. 기존 목록 전체 교체 정책을 이번 결정으로 변경한다.

## 범위·사용자 동작

- 검증 및 파일 관리 맨 아래에 `전체 검수 초기화` 버튼을 둔다. 현재 검수 내용을 지우고 전체 수집 목록을 복원한다는 확인창과 JSON 백업 안내를 표시한다.
- 확인하면 서버의 현재 수집 대상 전체를 초기 검수 상태로 준비한다. 이미지·툴팁·공유 스킬 출처는 유지한다. 초기화 후 응결 필터를 표시하고 검증 결과·자동 배정 해제 이력을 비운다. 브라우저에 자동 저장한다.
- 초기 자료 준비 실패 시 기존 목록과 편집을 유지한다. 취소 시 아무 변경도 하지 않는다. 저장 실패 시 화면 내용을 유지하고 기존 재시도 기능을 제공한다.
- JSON Import는 characterId로 병합한다. 같은 ID는 파일의 검수 내용·원본·이미지로 갱신하고, 새로운 ID는 목록 끝에 추가한다. 파일에 없는 대상의 편집·순서·임시 자동 배정 해제 이력·검증 결과는 유지한다.
- 같은 ID의 현재 편집이 덮어써질 수 있으므로 기존 편집 확인창의 안내를 병합 의미로 수정한다. 파일 전체 검증 성공 후 화면을 한 번에 갱신한다. 실패하면 기존 상태를 유지한다.
- Import 대상의 검증 결과만 비우고 현재 선택 공명자는 유지한다. 합쳐진 전체 목록을 브라우저에 저장·복원한다. 백업도 전체 목록을 포함한다.

## 구현 및 데이터 영향

초기화 API는 디스크 수집 원본에서 새 검수 상태와 자체 복원 가능한 백업을 준비한다. 이전 Import 메모리 자료를 초기화 원본으로 사용하지 않는다. Import API와 저장소는 파일에 없는 기존 Import 이미지 접근을 보존한다. 브라우저 Work는 공명자 ID 기준으로 병합한다. Rotation DB 및 원본 수집 파일에 변화는 없다.

## 비범위

개별 공명자 초기화, Undo, 자동 초기화, 앱 DB 삭제, 원본 이미지 재수집, JSON 자동 승인.

## 예외와 테스트

초기화 확인 취소·성공·실패, 이전 Import 원본과 수집 원본 구분, 저장 후 복원, Import 같은 ID 갱신·새 ID 추가·누락 ID 유지·실패 원자성, 여러 파일 연속 Import 후 이미지/백업 접근을 검증한다. lint/test/build를 실행한다.
