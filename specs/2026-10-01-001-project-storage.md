# 프로젝트 저장·관리와 자동저장

## 기능 목적

편집한 로테이션을 IndexedDB에 보존하고 여러 프로젝트를 생성·이름 변경·복제·삭제·다시 열 수 있게 한다. 작업 브랜치는 `codex/project-storage`다.

## 관련 PRD 요구사항

- 체크리스트 5절 및 PRD 12.1–12.3절: 여러 프로젝트, 자동 이름, 생성/수정 시각, Repository 계층, 참조 snapshot, suppression 보존, 자동저장 후 편집 이력 유지.
- I1–I5와 공명자 ID 소유권을 저장·복원 과정에서도 유지한다.

## 범위

- 버전이 있는 RotationProject와 Repository 인터페이스, IndexedDB 구현.
- 프로젝트 CRUD와 자동저장, 새로고침 후 저장 데이터 복원.
- 도메인 snapshot과 표시용 최소 참조 snapshot을 분리한다. 현재 catalog를 우선하고 다른 Skill로 자동 대체하지 않는다.
- 실패한 저장이 기존 데이터나 현재 편집을 초기화하지 않도록 한다.

## 비범위

JSON Import/Export UI, PNG Export, 실제 공명자 데이터 수집, 배포, 영구 Undo/Redo 이력, 다중 탭 동시 편집 정책.

## 사용자 동작 및 UX

새 프로젝트는 `새 로테이션 N`으로 생성하고 이름 변경을 지원한다. 복제는 새 ID로 독립 데이터를 저장하며 원본을 변경하지 않는다. 자동저장은 Undo/Redo의 한 편집 단계가 아니며 현재 이력을 유지한다.

제목 오른쪽 끝에 프로젝트 선택·새로 만들기·복제·이름 변경·삭제 조작을 둔다. 프로젝트를 다시 열 때마다 Undo/Redo를 초기화한다. 이름 변경과 자동저장은 현재 이력을 유지한다. 복제본의 이름은 즉시 원본의 현재 이름에 ` - 복제본`을 덧붙인다. 복제본을 다시 복제하면 표시를 다시 덧붙이며, 같은 이름을 허용하고 중복 방지 번호를 자동 추가하지 않는다. 이름은 이후 수정할 수 있다.

삭제 확인창에는 대상 이름을 표시한다. 열린 프로젝트 삭제 후 편집 화면을 닫고 목록에서 다른 프로젝트를 선택하도록 하며 마지막 프로젝트 삭제 후에도 자동 생성하지 않는다. 저장 실패는 오류와 재시도 버튼으로 알리고 현재 편집을 유지한다. 전환·삭제·생성·복제 전에 미저장 편집을 저장하며 실패하면 현재 프로젝트를 유지한다.

새로고침·앱 재시작 시 마지막으로 연 프로젝트를 복원한다. 마지막 프로젝트가 없으면 목록과 생성 조작을 표시한다. 데이터만 복원하고 Undo/Redo는 비운다. 저장 대기·저장 중·저장됨을 표시한다. 자동저장은 마지막 변경 후 300ms로 구현한다.

### 한 줄 헤더와 프로젝트 드롭다운

제목 오른쪽에 저장 상태와 현재 프로젝트 이름 드롭다운을 한 줄로 둔다. 저장 상태는 맨 왼쪽이며 두 칸의 너비는 고정한다. 별도 프로젝트 필드와 개발 검증 데이터 표시는 제거한다.

드롭다운은 고정 너비로 화면 위에 겹쳐 열린다. 상단에 현재 프로젝트 이름 입력창을 두고 수정·복제·삭제 버튼을 한 줄로 둔다. 프로젝트 목록에만 최대 높이와 세로 스크롤을 적용하며, 새 프로젝트 버튼은 목록 아래에 항상 보이도록 둔다. 헤더와 목록의 긴 이름은 말줄임하고 hover 시 전체 이름을 제공한다. 입력창에서는 전체 이름을 편집할 수 있다. 미선택 상태에서는 수정·복제·삭제가 비활성화된다.

외부 클릭이나 Escape로 닫으며 Escape는 열기 버튼으로 포커스를 돌린다. 선택창이 열린 동안 사이클 입력을 차단한다. 전환·생성·복제 성공 시 닫고 실패 시 현재 데이터와 선택창을 유지한다. 기존 저장 실패·삭제 확인·이력 정책은 유지한다. 오류·재시도는 제목 아래에 둔다. 이번 디자인은 별도 커밋으로 분리해 롤백할 수 있게 한다. Export 조작의 구체 배치는 후속 결정이다.

## 도메인 데이터에 미치는 영향

프로젝트는 ID, 이름, createdAt/updatedAt, app/schemaVersion, Rotation과 최소 참조 snapshot을 가진다. Timeline, Transition, AutoAction, stage, suppression을 그대로 저장하며 로드 시 catalog로 재생성하지 않는다. Undo/Redo는 저장 데이터에 넣지 않는다.

## 주요 구현 방법

- 순수 프로젝트 생성·복제·검증·snapshot 함수와 영속 접근을 분리한다.
- IndexedDB의 transaction 완료를 저장 성공으로 판정한다. 쓰기는 직렬화해 이전 저장이 최신 내용을 덮어쓰지 않게 한다.
- 편집 상태를 저장 완료 응답으로 덮어쓰지 않는다. 초기 로드 동안 입력을 받지 않는다.
- DB 오류·손상 레코드는 명시적인 오류로 전달하며 자동 삭제하거나 초기 데이터로 덮어쓰지 않는다.
- 개발 demo 데이터는 운영 데이터와 분리해 테스트한다.

## 예외 및 edge case

빈 목록, 같은 이름, 빈 이름, 저장 중 연속 편집, 저장 실패, 프로젝트 전환 중 입력, 삭제 취소, 마지막 프로젝트 삭제, 구버전/손상 데이터, catalog에서 사라진 ID, 삭제된 자동 행동의 suppression.

## 테스트 계획

- 순수 생성·복제·검증과 두 Cycle/소유권/stage/Transition/suppression round trip.
- IndexedDB CRUD, transaction 실패와 기존 데이터 보존.
- 연속 쓰기 순서와 자동저장 후 Undo/Redo 유지.
- 관리 UI, 새로고침 복원 및 실패 안내를 검증한다.
- lint/test/format:check/build를 실제 실행한다.

## 남아 있는 미확정 사항

다중 탭 충돌 해결, 영구 이력, JSON 오류·missing의 최종 디자인은 후속 작업이다. 실제 공명자 데이터는 없으므로 일반 화면은 미지정 파티로 시작한다. `?demo=storage`는 데모 파티와 별도 IndexedDB를 사용하며 기존 일회성 demo는 저장하지 않는다.
