# Encore 기반 자동 배정과 검수 카드 정렬

## 목적과 기준

기존 `2026-10-01-002-character-data-pipeline.md`의 검수 도구를 보완한다. 같은 작업 브랜치 `codex/character-data-pipeline`에서 진행한다. 요구사항 체크리스트 6절과 PRD 13·14절을 따르며, 2026-10-01 사용자가 승인한 Encore 명시 정보 자동 배정과 자동 행동 연결 규칙을 기준 문서에도 반영한다.

## 범위와 UX

- `Encore 자동 배정`으로 현재 수집 실행의 Encore 원본 `Skills`와 후보의 정규화된 아이콘 경로를 대조한다. 분류·실제 이름이 명시되고 단일 스킬로 일치할 때만 적용한다. 파일명·입력키·유사 이미지로 의미를 추론하지 않는다.
- 스킬 분류 `category`와 실제 스킬명 `displayName`을 별도로 저장하고 편집한다. 기본 공격, 공명 스킬, 공명 해방, 고유 스킬, 변주 스킬, 반주 스킬, 공명 회로, 조화도 파괴를 지원한다. 기존 미분류 데이터는 계속 읽는다.
- 고유 스킬은 분류·이름을 채우되 신규 등록 기본값은 제외한다. 나머지 일치하는 신규 미검수 후보는 노출로 배정한다. 불일치·다중 의미·다운로드 실패는 자동 확정하지 않고 사유를 보여준다.
- 기존 이름이 비어 있거나 기존 분류명 자체일 때 실제 이름을 채운다. 사용자가 입력한 다른 이름·후보 제외 선택과 기존 공개 ID는 보존한다. 기존 스킬은 정확한 생성 ID 또는 사용자가 명시한 후보 연결로만 대응한다.
- 자동 행동은 기본 공격 → 일반 교체 공격, 변주 스킬 → 변주, 반주 스킬 → 반주다. 분류별 노출 스킬이 정확히 하나일 때 연결하며, 없음·중복은 오류로 남겨 사용자가 분류·노출을 수정한다. 미분류 구버전 파일은 기존 매핑을 유지한다.
- 기존 검수 스킬과 수집 후보 각각의 카드에서 이동 손잡이를 드래그하거나 앞/뒤 이동 버튼으로 순서를 바꾼다. 두 목록 구분은 유지한다. 검수 저장·재열기·최종 반영 후에도 목록별 순서를 유지한다.
- 자동 배정과 이동은 편집 변경으로 취급하며 저장·검증·최종 확인 절차를 거친다. 기존 검수 파일을 열기만 해서는 변경하지 않는다.

## 도메인과 구현

- Character v1에 선택적 `category`를 추가해 기존 JSON과 호환한다. 검수 상태·catalog에도 분류를 보존한다. Rotation·프로젝트 snapshot의 의미·입력과 스킬 연결 방식은 변경하지 않는다.
- Encore 원본을 서버에서 읽어 후보별 검증 근거를 만든다. 수집 원본과 이미지를 다시 수집하거나 덮어쓰지 않는다. 최종 반영 시 분류와 이름, 순서를 JSON에 포함한다.
- 검수 배열의 순서를 배치 순서로 사용한다. ID 집합 검증은 순서와 독립적으로 유지한다. 기존 스킬 ID 삭제·rename을 허용하지 않는다.
- 기존 최종 파일 및 사용자 검수는 직접 일괄 수정하지 않는다. 사용자가 화면에서 배정 결과를 검토하고 반영한다.

## 아이콘 조사 및 비범위

6명의 Encore `Skills`와 WW_Data의 스킬 그룹·버튼 태그·아이콘 테이블 및 관련 추가 테이블을 확인한다. 공명 스킬 2단의 정확한 공명자/아이콘이 아직 지정되지 않았으므로 전체 자산 부재를 단정하지 않는다. 추가 원본 경로가 확인되면 후보 수집을 보완하되 이름만 바꾼 추측 경로를 완전한 수집으로 보고하지 않는다.

게임 자산 전체 추출, 임의의 강화 스킬 의미 확정, 로테이션 자동 생성, 새로운 UI 아이콘 선택, Export·배포는 이번 범위가 아니다.

## 예외와 테스트

- 같은 아이콘을 여러 Encore 스킬이 공유할 때 자동 배정 차단, 고유 스킬 기본 제외, 분류·실제 이름 분리, 이미 검수한 이름·ID 보존.
- 고정 자동 행동 연결, 중복 분류와 누락 거부, 구버전 JSON·검수 상태 호환.
- 카드 이동 후 미저장 경고, 저장/재열기 및 최종 반영의 순서 유지, 검증 무효화.
- 원본 손상은 자동 배정에 오류로 표시하고 기존 검수 수동 편집은 유지한다.
- lint/test/format/build와 실제 검수 화면을 확인한다.

## 아이콘 조사 결과 (2026-10-01)

- 6명의 수집 실행에 저장된 `encore.json` 전체를 검사했다. 각 응답에 나타나는 `SkillIcon/` 자산 경로는 10개이며 모두 해당 `draft.json` 후보에 포함되어 있다. 대표 스킬 목록 외 중첩 데이터에 들어 있는 경로도 대조했다. 현재 응답에 있는 경로를 수집기가 누락한 사례는 발견하지 못했다.
- 같은 원본은 각 공명자에 10개의 명시적 SkillType/SkillName 항목을 제공한다. 이 중 고유 스킬은 3개이며 신규 기본 노출은 나머지 7개다. 이는 대표 아이콘/분류 개수로, 게임 내 모든 강화·다단계 아이콘의 개수를 뜻하지 않는다.
- [WW_Data](https://github.com/Arikatsu/WutheringWaves_Data)의 고정 commit `9218d612ad815e398e064e577e42aaf878899968`에서 `skillbutton.json` 293행, `skillicon.json` 84행을 확인했다. 현재 수집은 공명자 RoleId의 태그와 확인된 전용 아이콘 폴더를 통해 후보를 포함한다.
- 추가로 같은 commit의 `skillbuttoncustom.json`, `skillcommonbutton.json`, `skillprioritybutton.json`, `skilldescription.json`, `roleskillfighttrick.json`을 조회했으나 6명의 전용 아이콘 경로를 새로 얻지는 못했다. 응답은 로컬 `.character-sync/`의 같은 파일명에 보존했다. `aki_base.csv`는 테이블과 DB의 대응 목록이며 이미지 파일 목록이 아니었다.
- 모니에의 `A2/A4/C2`, 청초의 `E1` 경로는 이미 WW_Data 후보에 있다. 이 suffix는 발견 근거일 뿐 해당 이미지의 게임 내 의미를 확정하지 않는다.
- 결론: 현재 조회한 Encore·WW_Data 메타데이터에는 전체 상황별 아이콘 목록이 보장되지 않는다. **게임 자산이나 Encore 이미지 서버 자체에 이미지가 없다는 결론은 내릴 수 없다.** 보고된 공명자·스킬 또는 화면을 확인한 다음 정확한 원본 자산 경로나 추가 출처를 대조해야 한다. 이번 변경에서 확인되지 않은 아이콘을 추가 수집했다고 보고하지 않는다.
