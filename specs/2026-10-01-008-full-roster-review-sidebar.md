# 전체 공명자 검수와 사이드바 정리

## 목적과 기준

사용자가 요청한 전체 공명자 검수를 지원한다. PRD 13·14절, 체크리스트 6절 및 기존 검수 JSON 전달 규칙을 따른다. 현재 데이터 파이프라인 브랜치에서 진행한다.

## 범위와 UX

- Encore 공명자 목록의 전체 ID를 수집 대상으로 삼는다. 같은 이름의 다른 ID도 별도 항목으로 유지한다. 이전 원본과 앱 DB는 보존한다.
- 왼쪽 필드는 `자동 행동 연결 → 검증·파일 관리 → 공명자 목록` 순서로 배치한다.
- 검증 결과 영역과 공명자 목록 영역에 각각 높이 제한·세로 스크롤을 적용한다. 필드 제목과 실행 버튼은 결과 스크롤 밖에 둔다.
- 공명자 항목 왼쪽에는 이름, 오른쪽에는 `미검증 / 오류 / 통과`를 표시한다. ID는 툴팁으로 확인 가능하게 하여 같은 이름도 구분한다.
- 아직 검증하지 않았으면 미검증, 현재 내용의 검증 오류가 있으면 오류, 검증을 통과했으면 통과다. 검증 전 기존 원본/DB 오류가 확인된 대상은 오류로 표시한다. 실패 후보를 제외하는 등 편집한 뒤 실제 검증을 통과하면 현재 결과인 통과를 우선한다. 상태는 DB 등록 완료나 자동 배정 여부를 의미하지 않는다.
- 편집이나 자동 배정 후에는 해당 대상의 이전 검증 결과를 무효화해 다시 미검증으로 표시한다. 다른 대상의 결과는 유지한다. Import는 기존 정책대로 전체 목록을 교체하고 검증 표시를 초기화한다.

## 데이터 및 구현

검증 상태는 현재 페이지의 기존 검증 결과와 수집 오류에서 파생한다. 원본 수집은 기존 CLI를 사용하고 데이터 접근 실패는 사실대로 표시한다. 수집 실패를 통과로 처리하거나 임의로 스킬을 승인하지 않는다.

## 추가 요청: 브라우저 저장과 속성별 목록

- 사용자의 후속 지시에 따라 페이지 메모리만 사용하던 검수 편집을 전용 IndexedDB에 자동 저장한다. 현재 목록·미완성 편집·카드 순서·자동 행동·원본 후보·이미지·툴팁과 선택한 공명자를 저장하고 새로 열 때 복원한다. 앱 Rotation 저장소와 분리한다.
- 검수 버전 이력을 쌓지 않고 최신 편집 상태 한 개를 갱신한다. 검증한 대상 ID를 함께 저장하고 복원 시 해당 대상만 다시 검증하여 오류/통과 상태를 복구한다. 미검증 대상은 그대로 유지한다. 자동 배정 해제용 임시 이력은 초기화한다.
- 일반 수집 목록은 새 workspace에 추가된 공명자를 포함하면서 같은 ID의 저장 검수를 보존한다. 사용자가 JSON으로 불러온 목록은 기존 확정 정책대로 파일의 전체 목록을 유지한다.
- 원본·이미지는 목록 구성 시 한 번 준비하고 편집 시 검수 값만 갱신해 IndexedDB에 기록한다. 저장 중/저장됨/저장 실패를 표시하고 실패 시 편집 내용을 화면에 유지하며 재시도를 제공한다. 복원 실패 시 저장본을 자동으로 덮어쓰지 않는다.
- 공명자 목록은 응결·용융·전도·기류·회절·인멸 순서의 접고 펼치는 그룹으로 나눈다. 그룹에 항목 수를 표시하고 처음에는 펼친다. 이름과 미검증/오류/통과 표시는 유지한다.
- 저장/복원·실패 시 기존 저장본 유지·JSON Import 자료 복원·새 수집 대상 병합·속성 그룹 순서를 테스트한다.

## 비범위

앱 DB 등록, 수집된 모든 스킬의 자동 승인, 이름 검색, 검수 버전별 이력, 배포.

## 예외와 테스트

전체 수집의 원본/API 실패와 부분 이미지 실패를 보고한다. 긴 이름과 같은 이름·다른 ID를 유지한다. 사이드바 순서, 검증 전/오류/통과 표시, 편집 후 결과 무효화 및 대상 전환 유지, Import 초기화, 독립 스크롤을 검증한다. lint/test/build 및 실제 전체 목록의 개수와 수집 상태를 확인한다.

## 미확정 사항

없음. 외부 소스 접근 여부는 실제 수집 시 확인한다.

## 구현 검증 결과

- 전체 64개 ID를 수집했다. 63개는 수집 완료, 1502는 Encore 스킬 후보가 비어 있어 부분 수집으로 기록했다. 검증된 이미지 1,181개를 확보했으며, 수집 완료는 사람 검수 통과를 의미하지 않는다.
- 브라우저에서 64개 항목, 속성별 그룹, 목록·결과의 독립 스크롤과 새로고침 후 자동 복원을 확인했다.
- 단위 테스트 242개, lint, 앱 build, 검수 도구 build, format 검사를 통과했다. 검수 도구 build에는 기존 Vite의 향후 config loader 호환성 안내가 남아 있다.
