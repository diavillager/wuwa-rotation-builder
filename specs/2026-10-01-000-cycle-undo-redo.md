# 사이클별 Undo/Redo 명세

## 기능 목적

개막·반복의 사이클 편집을 각각 되돌리고 다시 실행한다. 파티 변경은 이력 대상에서 제외한다. 작업 브랜치는 `codex/cycle-edit-history`다.

## 관련 PRD 요구사항

- `docs/requirements-checklist.md` 4–5절: Shared Timeline, 교체·자동 행동, 사이클별 Undo/Redo.
- `docs/PRD.md` 7절, 10절, 12.3절: 파티 변경, linked AutoAction·suppression의 원자적 복원과 이력 범위.
- `specs/2026-09-30-004-manual-transition-editing.md`: 기존 입력·교체·드래그 및 스크롤.

## 범위

- 각 사이클 제목 오른쪽에 실행 취소·다시 실행 아이콘 버튼을 둔다. 텍스트는 표시하지 않고 접근성 이름과 툴팁으로 동작을 안내한다. 이력이 없으면 해당 버튼을 비활성화한다.
- InputBlock 생성·삭제·이동, SkillBlock 추가·삭제·재정렬·stage 변경, 숫자키 교체와 AutoAction 생성·삭제를 한 도메인 명령당 한 단계로 기록한다.
- 일반·협주 교체의 Transition과 자동 행동을 함께 복원한다. linked pair 삭제와 suppression도 함께 복원한다.
- 개막의 새 편집은 개막 Redo만 비우고 반복 이력은 유지한다. 반복도 동일하다.
- 파티 순서만 바꾸면 두 이력을 유지한다. 복원 시 현재 파티 순서를 유지하며 공명자 ID 소유권을 사용한다.
- 파티 슬롯 공명자가 실제 변경되면 두 사이클의 Undo/Redo 이력을 모두 초기화한다. 현재 남은 사이클 내용은 보존하며 이후 편집부터 새 이력을 쌓는다.
- 같은 공명자 선택, 변경 취소와 실패한 명령은 이력을 변경하지 않는다. 기존 내용이 있는 공명자 변경 확인창에는 두 사이클 이력 초기화 안내를 덧붙인다. 빈 공명자의 경고 없이 변경하는 기존 규칙은 유지한다.

## 비범위

- 파티 변경 Undo/Redo, 프로젝트 관리 작업의 Undo/Redo.
- 단축키, 여러 wheel 이벤트의 이력 묶음, 이력 목록 UI.
- IndexedDB·JSON/PNG Export·프로젝트 관리, 실제 공명자 데이터 수집 및 배포.

## 사용자 동작 및 UX

개막에서 E를 입력하고 반복에서 R을 입력한 뒤 개막 실행 취소를 누르면 E만 사라지고 R은 남는다. 개막에서 다시 실행하면 E를 원래 위치·소유자·Skill·stage와 함께 복원한다.

커서 활성 라인·스킬 진열, 페이지·Cycle 스크롤 및 선택창 열기/닫기는 이력에 넣지 않는다. Undo/Redo는 현재 활성 공명자를 유지하며 기존 커서 기반 활성화 규칙은 계속 적용한다. 버튼 클릭은 실제 입력으로 캡처하지 않고 진행 중 미확정 입력을 취소한다. 모달·선택창·드래그 중에는 이력 조작을 차단한다.

파티 A/B/C를 C/A/B로 재정렬한 뒤 Undo해도 현재 파티 순서는 C/A/B다. B를 D로 변경하면 이전 사이클 이력을 비우므로 Undo로 B의 행동을 복원할 수 없다.

## 도메인 데이터에 미치는 영향

이력은 Rotation 저장 데이터와 분리한 메모리 상태다. Cycle의 `columns`, `transitions`, `suppression`만 snapshot으로 보관하며 `activeCharacterId`와 party를 복원하지 않는다. 기존 순수 연산의 불변 snapshot을 재사용한다. 모든 상태 전환 후 `assertRotation`으로 I1–I5·참조 무결성을 확인한다.

## 주요 구현 방법

1. 순수 편집 이력 모듈에 Rotation과 Cycle별 past/future를 관리한다.
2. UI의 Rotation 변경 진입점을 이력 기록으로 연결한다. 내용이 실제로 바뀌지 않은 명령과 활성 라인 변경은 제외한다.
3. 파티의 공명자 ID 집합 변경은 두 이력을 비우고, 순서만 변경하면 유지한다.
4. Undo/Redo는 해당 Cycle의 내용과 past/future를 한 상태 전환으로 반영한다. 다른 Cycle과 현재 party·active line은 유지한다.
5. UI는 버튼 활성 여부를 이력에서 읽으며 도메인 복원 로직을 직접 구현하지 않는다.

## 예외 및 edge case

- 빈 이력, Undo 후 새 편집, stage 0 감소, 같은 위치 이동, 실패한 명령.
- 일반 교체와 협주 pair 생성·삭제·suppression, 이미 끊어진 구간의 복원.
- 파티 재정렬 뒤 반복 Undo/Redo, 내용이 없지만 과거 이력이 있는 공명자 변경.
- 두 Cycle 교차 편집, 활성 라인 변경 중 Redo 유지, 새로고침 후 이력 없음.

## 테스트 계획

- Cycle별 입력·삭제·재정렬·스킬 변경 복원과 다른 Cycle 독립성.
- 교체·자동 행동의 원자성, pair·suppression 및 소유권·anchor 복원.
- no-op·hover·실패에서 이력 유지, Undo 후 새 편집의 해당 Cycle Redo 초기화.
- 파티 재정렬 이력 유지와 현재 순서 보존, 공명자 변경 시 두 past/future 초기화, 취소·같은 선택 유지.
- 실제 UI 버튼 위치·disabled 상태·입력 오캡처 방지·확인창 문구를 검증한다.
- lint / test / format:check / build 실행 후 브랜치를 push한다.

## 남아 있는 미확정 사항

키보드 단축키, 이력 최대 개수, 반복 편집 묶음 및 저장소 연동은 후속 작업이다. 이번 단계에는 이력 상한을 새 제품 규칙으로 도입하지 않는다.
