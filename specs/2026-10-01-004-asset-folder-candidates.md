# 실제 자산 폴더 기반 후보 수집 보완

> 검수 저장·이력·웹 최종 반영 및 화면 구성은 후속 [검수 JSON 전달 spec](2026-10-01-005-review-json-handoff.md)의 확정 흐름으로 대체되었습니다.

## 목적과 기준

PRD 13·14절과 요구사항 체크리스트 6절의 넓은 후보 수집·검수 보존을 보완한다. 모니에에서 메타데이터에 없는 A1/A3/B2/T 파일이 기존 전용 폴더에 존재함을 확인했다. 사용자는 이 방법을 청초·데니아·모니에·루파·장리·브렌트 6명에 적용하도록 요청했다. 기존 `codex/character-data-pipeline` 브랜치에서 구현한다.

## 범위와 사용자 흐름

- Encore·WW_Data의 기존 합집합에 WW_Asset_Webp 전용 폴더의 실제 개별 WebP 목록을 추가한다. 기존 메타데이터에서 확인된 전용 폴더만 탐색하며 공용 SkillIconNor 전체를 특정 공명자에게 배정하지 않는다.
- 자산 저장소 commit을 고정하고 파일 목록과 출처를 실행에 보존한다. 파일명 변경을 추측해 요청하지 않는다. Atlas 합본은 개별 스킬 후보에서 제외한다.
- 6명을 하나의 수집 실행으로 구성한다. 기존 실행과 최종 등록 파일은 보존한다.
- 같은 후보 ID·이미지와 최종 데이터 기준이 유지될 때 가장 최근 저장 검수의 이름·분류·노출·자동 행동·카드 순서를 새 실행에 복사하고 새 후보는 마지막에 미검수 상태로 추가한다. 저장되지 않은 브라우저 편집은 이전하지 않는다.
- 기존 검수·이미지·최종 데이터가 변경되거나 손상되어 안전한 이전이 불가능하면 오류로 기록하고 원본을 보존한다. 조용히 이전 완료로 표시하지 않는다.

## 구현과 데이터 영향

- git의 blob 제외 shallow fetch와 ls-tree로 파일 목록만 읽는다. 전체 이미지 저장소를 checkout하지 않는다. 실행별 후보와 이미지 검증은 기존 수집 경계를 유지한다.
- 정규화한 게임 경로와 종류로 후보 ID를 유지한다. 기존 경로와 중복이면 출처만 병합한다. 새 자산 후보의 이미지는 고정 commit의 raw URL에서 다운로드한다.
- HTTP·Content-Type·WebP 디코딩·hash 검증을 유지한다. 탐색/다운로드 실패는 report와 검수 초안에 남긴다.
- 기존 최종 Character JSON과 Rotation·Timeline·InputBlock·AutoAction은 변경하지 않는다. 추가 이미지의 스킬명·분류·노출을 파일명만으로 추정하지 않는다.

## 비범위와 미확정

전체 공명자 등록, 모든 상황별 아이콘의 완전성 보장, 공용 폴더의 미참조 파일 배정, Atlas 자르기, UI 공통 아이콘 선택, 자동 최종 반영, Export·배포는 제외한다. 다른 폴더의 미참조 아이콘 존재 여부는 후속 조사로 남긴다.

## 예외와 테스트

- 메타데이터에 없는 같은 폴더 아이콘 추가, 다른 공명자/공용 폴더 배제, Atlas 배제, 중복 ID 보존.
- git/source 오류를 부분 실패로 기록, 이미지 오류 기록, 고정 ref 및 경로 검증.
- 저장 검수 순서·이름·분류·선택 보존, 새 후보 pending, 이미지 변경·누락·기준 충돌 시 이전 차단, 원본 파일 보존.
- 6명 실제 수집 및 전체 WebP 검증, 검수 API에서 6명과 새 이미지 로딩 확인.
- lint/test/format:check/build/character-review:build 실행.
