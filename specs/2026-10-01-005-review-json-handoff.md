# 지정 공명자 검수와 JSON 전달 방식

## 목적과 기준

2026-10-01 사용자의 검수 흐름 변경 요청을 적용한다. PRD 13·14절과 체크리스트 6절을 이번 확정 사항에 맞춰 갱신한다. 기존 `codex/character-data-pipeline` 브랜치에서 진행한다. 이 문서의 흐름은 이전 spec의 실행 이력 선택·검수 저장·웹 최종 반영·검수 이어받기를 대체한다.

## 범위와 사용자 동작

- 에이전트가 요청받은 공명자 목록을 현재 검수 대상으로 구성한다. 화면 왼쪽에는 해당 목록만 표시하며 날짜별 실행·과거 검수 목록은 제거한다. 수집 원본·이미지는 검증용 자료이며 사용자 검수 이력과 구분한다.
- 웹은 앱 DB나 Git에 쓰지 않는다. 누락 검증과 JSON Export만 제공한다. 사용자가 Export 파일을 에이전트에게 전달하면 에이전트가 이미지·참조·기존 ID를 다시 검증한 후 DB를 갱신한다. Export 완료는 DB 반영 완료가 아니다.
- 편집은 페이지 메모리에만 두고 같은 페이지에서 공명자를 오갈 때 유지한다. 새로고침/종료 후 복원할 검수 이력을 서버나 브라우저 저장소에 만들지 않는다. 내보내지 않은 편집이 있으면 페이지 이탈 경고를 유지한다.
- Encore 자동 배정과 해제를 제공한다. 해제는 이후 직접 편집한 필드와 카드 순서를 보존하고 자동 변경 값만 복원한다.
- 카드 이동은 손잡이 드래그로 제공하고 앞/뒤 화살표 버튼을 제거한다.
- 카드 순서: 이동 → 아이콘·후보 번호·데이터 소스 → 처리 여부 → 분류 → 스킬명 → 출처와 후보 이름. 처리 여부는 가로 체크박스 `등록 / 미등록`이며 상호 배타적이다. 둘 다 해제하면 미검수다.
- 두 체크박스는 같은 높이에 정렬한다. 미등록 카드는 어두운 배경·점선 테두리·흐린 무채색 아이콘·미등록 배지로 구분하되 수정과 재등록은 가능하다.
- 분류 선택 순서는 미분류, 기본 공격, 공명 스킬, 공명 해방, 공명 회로, 변주 스킬, 반주 스킬, 조화도 파괴, 고유 스킬이다.
- Encore 자동 배정 버튼은 배정 후 위 분류 순서로 전체 카드를 정렬한다. 같은 분류 안에서는 현재 카드 순서를 유지한다. 자동 배정 해제는 정렬을 되돌리지 않으며, 정렬 이후 직접 바꾼 배치도 유지한다. Export 역시 현재 카드 순서를 따른다.
- 왼쪽에 `검수 대상`, 그 아래 `자동 행동 연결`과 `검증 및 내보내기`를 배치한다. 오른쪽은 `공명자 정보`, `스킬 아이콘 검수`로 구성하고 남는 폭을 채운다. 제목에 실행 이력을 암시하는 문구를 사용하지 않는다.

## 주요 구현과 데이터 영향

- 현재 대상 manifest는 수집 원본 위치만 지정한다. 수집기가 새 지정 목록으로 교체하고 검수 API는 이 목록만 노출한다.
- 검수 load는 수집 원본과 현재 DB를 읽어 시작 상태를 만든다. save/publish API와 자동 검수 이어받기·검수 상태 파일 쓰기를 제거한다.
- Export는 출처·안정적인 ID·검수 값·카드 순서를 담은 버전 있는 JSON이다. 실제 DB용 approved 데이터와 구분한다. 웹은 수집 원본과 최종 DB를 변경하지 않는다.
- Rotation·Timeline·Transition·AutoAction·입력 스킬 연결의 의미는 변경하지 않는다. 기존 공개 ID는 DB 갱신 시 보존한다.

## 비범위

검수 이력 조회·저장·복원, 웹에서 DB 직접 반영, Git 자동 commit/push, 앱 Rotation JSON/PNG Export, 전체 공명자 자동 의미 승인, 배포는 제외한다.

## 예외와 검증 계획

- 지정 목록 밖 대상의 load/image/검증/Export 거부. 과거 실행을 목록에 노출하지 않는다.
- 누락/이미지 실패/잘못된 참조/원본·DB 변경 검증. Export 이후에도 파일을 신뢰하지 않고 재검증해야 함을 문서화한다.
- JSON 다운로드와 검증 API에서 DB·수집 원본·검수 상태 파일 쓰기가 없는지 확인한다.
- 처리 체크박스의 상호 배타성과 해제, 자동 배정 해제, 카드 순서, 페이지 내 대상 전환 상태 유지, Export 오류 시 편집 보존 테스트.
- 사용자가 삭제를 요청한 기존 review.json 및 검수 백업·이어받기 내역을 경로 확인 후 제거한다. 사용자 승인에 따라 장리(1205)·브렌트(1206)·루파(1207)의 기존 앱 DB 데이터도 제거한다.
- lint/test/format/build, 검수 build와 실제 화면 확인.

## 확정 사항과 구현 결과

- 지정 목록에서 검증을 통과한 모든 공명자를 하나의 JSON 파일로 내보낸다. 미완성 대상은 제외한다. 필수 이미지의 실제 WebP와 SHA-256도 포함하여 파일만 전달해 재검증할 수 있게 한다. `pending-agent-validation` 상태를 사용한다.
- 기존 스킬과 새 후보를 구분한 필드를 제거하고 하나의 스킬 검토 영역과 카드 순서로 통합한다. 기존 공개 ID 보존을 위한 내부 구분은 UI에 별도 필드로 표시하지 않는다.
- 지정한 6명(청초·데니아·모니에·루파·장리·브렌트)의 수집 원본은 유지한다. 이전 검수·백업 파일 13개와 기존 앱 DB 3명을 삭제하고 빈 검수 상태로 시작한다.
- 자동 배정 해제는 직접 편집을 필드 단위로 기록하여 보존하고 카드 순서를 바꾸지 않는다.

## 남아 있는 사항

실제 스킬 의미 검수와 Export 파일 전달 후 DB 등록은 사용자가 검수한 뒤 진행한다. 전체 공명자 수집과 앱 Export는 이번 범위가 아니다.

## 실행한 검증

- `npm run lint`, `npm run format:check`: 통과.
- `npm run test`: 24개 파일, 212개 테스트 통과. 복수 대상 중 완료한 2명만 한 파일로 Export하고 미완료 1명을 제외하는 API 시나리오 포함.
- `npm run build`, `npm run character-review:build`: 통과. 검수 build의 향후 Vite native config loader 호환 경고는 남아 있으며 현재 bundle loader로 빌드한다.
- `npm run characters:validate`: 삭제 후 등록 데이터 0개, 오류 0개.
- skill-creator `quick_validate.py`: 통과.
- 로컬 실제 화면: 지정 6명 목록·단일 스킬 영역·자동 배정/해제 확인. 새로고침하여 미검수 초기 상태로 남겼다.
