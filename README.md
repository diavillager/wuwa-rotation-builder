# wuwa-rotation-builder

Wuthering Waves 3인 파티의 개막·반복 로테이션을 실제 입력 순서로 기록하기 위한 데스크톱 앱입니다.

## 개발 상태

Rotation 도메인 모델, 파티·타임라인 Editor, 실제 입력 캡처, 사이클별 Undo/Redo와 IndexedDB 프로젝트 저장·관리를 제공합니다. Export와 검수된 실제 공명자 데이터는 아직 제공하지 않습니다.

공명자 항목은 커서 진입 시에만 활성화하며 항목 위 입력은 현재 활성 공명자 소유로 전역 끝에 추가합니다. 숫자키 교체 후에도 커서를 옮기지 않고 도착 공명자로 입력을 이어갑니다. 블록 배치 영역에서는 커서 라인을 실시간으로 활성화합니다. 빈 셀에서는 그 라인의 마지막 편집 가능 위치에, InputBlock과 내부 스킬 위에서는 해당 입력 블록 바로 뒤에 삽입합니다. 배치 영역의 숫자키 교체 후에는 커서 라인을 유지합니다. 라인 밖에서는 마지막 활성 표시와 진열을 유지합니다.

## 개발 환경

Node.js 20.19 이상과 npm이 필요합니다.

```sh
npm install
npm run dev
```

로컬 개발 서버가 출력하는 주소를 브라우저에서 여세요.

개발 서버 주소 뒤에 `?demo=1`을 붙이면 가상 공명자·스킬과 로테이션이 담긴 검증 화면이 열립니다. 이 데이터는 실제 게임 데이터가 아니며 저장되지 않습니다. 일반 화면에는 검수된 공명자 데이터가 준비되기 전까지 미지정 슬롯이 표시됩니다.

`?demo=continuity`는 두 Cycle에 `A: LMB×3 → B: E → C: R`을 구성합니다. 파티 슬롯 2의 B를 응결의 데모 E로 변경하면 A와 C 입력은 유지되고 두 라인 사이 연결선이 끊어집니다.

`?demo=input`은 데모 A/B/C 파티와 빈 개막·반복 Cycle을 제공합니다. 편집할 공명자 라인의 빈 셀 또는 InputBlock에 마우스를 두고 `Q/E/R/T/F/Space/LMB/RMB`를 입력하면 현재 라인에 스킬 없는 입력이 생성됩니다. 200ms 전에 떼면 Tap을 생성하고, 계속 누르면 200ms에 release를 기다리지 않고 Hold를 생성합니다. 이후 release 시 중복 생성하지 않습니다. 숫자키 `1/2/3`은 Tap으로 일반 교체, Hold로 협주 교체를 만듭니다. 한 번에 하나의 입력만 받으며 누르는 동안 들어온 추가 입력은 무시합니다. 캡처 영역 밖이나 다른 라인으로 이동하면 아직 생성하지 않은 입력을 취소합니다.

직접 확인할 순서: 개막 빈 영역에서 A 라인에서 LMB 세 번 → `2` Tap → 커서를 B 라인으로 이동 → `E` Tap → `3` Tap → 커서를 C 라인으로 이동 → `R` Tap. A의 세 입력, B의 E, C의 R과 두 교체가 생기며 반복 Cycle은 비어 있어야 합니다. Q를 누른 채 E를 눌렀다 떼면 E는 무시되고 200ms에 Q Hold 하나만 생깁니다. 데이터는 저장되지 않으므로 새로고침하면 초기화됩니다.

연속 입력 예: A 공명자 항목에 커서를 두고 LMB 세 번 → 숫자키 2 → E → 숫자키 3 → R. 커서를 이동하지 않고 A/B/C 순서로 기록합니다. 실제 블록 뒤 수동 편집은 블록 배치 영역을 사용합니다.

블록 위에 커서를 두고 `Backspace`로 삭제합니다. 삭제 후 같은 커서 위치로 다음 블록이 이동하면 마우스를 움직이지 않고 계속 삭제할 수 있습니다. 협주 반주·변주는 한쪽 삭제 시 함께 삭제됩니다.

각 사이클 제목 오른쪽의 실행 취소·다시 실행은 해당 사이클의 편집만 복원합니다. 파티 순서를 바꾸어도 이력은 유지하며, 공명자를 다른 공명자로 변경하면 두 사이클 이력을 모두 초기화합니다. 같은 공명자 선택과 변경 취소는 이력을 유지합니다. 활성 라인·스크롤·파티 변경은 Undo/Redo 대상이 아니며 이력은 현재 세션에서만 유지됩니다.

## 프로젝트 저장과 관리

제목 오른쪽에서 새 프로젝트 생성·선택·이름 변경·복제·삭제를 사용합니다. 프로젝트는 브라우저의 IndexedDB에 저장됩니다. 새로고침하면 마지막으로 연 프로젝트의 내용을 복원하며, 프로젝트를 다시 열 때마다 Undo/Redo 이력은 초기화합니다. 이름 변경과 자동저장은 현재 이력을 유지합니다.

제목 오른쪽 한 줄에 저장 상태와 현재 프로젝트 이름을 표시합니다. 고정 너비 드롭다운 안에서 이름 수정·복제·삭제·프로젝트 선택·새 프로젝트 생성을 사용합니다. 목록에만 스크롤을 적용해 생성 버튼은 항상 보이며, 긴 표시 이름은 말줄임합니다.

복제하면 현재 원본 이름에 ` - 복제본`을 붙입니다. 복제본을 다시 복제하면 표시를 한 번 더 붙이며, 이름이 중복되어도 번호를 추가하지 않습니다. 프로젝트는 서로 다른 ID로 구분되고 이름은 직접 수정할 수 있습니다.

편집 후 300ms가 지나면 자동저장을 시작합니다. 화면의 `저장됨`을 확인하면 DB transaction이 완료된 상태입니다. `저장 대기` 또는 `저장 중`에 페이지를 닫으면 최신 변경이 아직 저장되지 않았을 수 있습니다. 저장 실패 시 현재 내용은 유지하고 재시도를 제공합니다. 프로젝트 전환·생성·복제·삭제는 미저장 내용을 먼저 저장하며 실패하면 현재 편집을 유지합니다. 삭제는 확인 후 진행하고, 마지막 프로젝트를 삭제해도 새 프로젝트를 자동 생성하지 않습니다.

`?demo=storage`는 데모 공명자 A/B/C로 저장 기능을 시험할 수 있는 화면입니다. 운영 프로젝트와 별도 DB를 사용합니다. 기존 `?demo=input`, `?demo=continuity`, `?demo=1` 화면은 계속 일회성 데이터입니다. 브라우저 데이터 삭제 또는 주소/포트 변경 시 기존 저장소에 접근할 수 없으며 다중 탭 동시 편집의 충돌 해결은 아직 지원하지 않습니다.

공명자·스킬 데이터가 없으면 저장된 표시 이름을 사용하고 데이터 누락을 표시합니다. 입력·교체·자동 행동·stage·suppression은 현재 catalog를 기준으로 재구성하지 않습니다. 실제 데이터가 없는 일반 화면의 새 프로젝트는 미지정 파티로 시작합니다.

```sh
npm run lint
npm run format:check
npm test
npm run build
```
