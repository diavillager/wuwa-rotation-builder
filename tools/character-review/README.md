# 로컬 공명자 검수 화면

수집된 실제 아이콘을 보고 사람이 스킬 이름·노출 여부와 일반 교체 공격·변주·반주를 각각 확정하는 개발 도구입니다. 앱의 Rotation이나 브라우저 프로젝트는 변경하지 않습니다.

## 실행

저장소 루트에서 실행합니다. 먼저 [후보 수집 도구](../../scripts/character-sync/README.md)로 검수 대상을 준비합니다.

```sh
npm run character-sync -- --character <ID>
npm run character-review
```

[검수 화면](http://127.0.0.1:5174/)을 엽니다. 서버는 `127.0.0.1:5174`에만 바인딩하며 다른 Host·Origin과 인증 토큰 없는 쓰기를 거부합니다. `localhost` 대신 위 주소를 사용하세요. 검수 API는 일반 앱의 개발 서버·배포 번들에 포함하지 않습니다.

## 검수 순서

1. 왼쪽에서 수집 실행과 공명자를 선택합니다. 가운데는 기존 검수 스킬과 새 후보, 오른쪽은 자동 행동과 오류입니다.
   재수집 시 안전하게 이어받을 수 있는 저장 검수는 새 실행에도 같은 순서로 표시하고 새 후보는 끝에 붙입니다. 실제 자산 폴더에서 추가된 후보는 출처에 `ww-asset`이 표시됩니다. 이름·노출은 자동 확정하지 않습니다. 이전 실패가 표시되면 원래 실행의 검수는 그대로 남아 있습니다.
2. 초상화를 선택하고 기본 이름·속성을 확인합니다. 새 스킬 후보마다 **새 스킬로 노출** 또는 **신규 등록에서 제외**를 선택합니다. `Encore 자동 배정`은 동일 아이콘의 명시적 분류와 실제 이름을 별도 필드에 채웁니다. 고유 스킬은 기본 제외합니다. 모호한 대응은 자동 배정하지 않습니다. 기존 직접 지정 이름·선택은 보존하며 빈 이름이나 분류명으로만 적었던 이름은 실제 명칭으로 채웁니다.
3. 기존 스킬은 이름·노출 여부·공개 ID를 유지한 채 시작합니다. 아이콘을 바꾸려면 후보를 직접 연결합니다. 공개 ID는 바뀌지 않습니다. 연결한 후보는 기존 스킬의 검수로 처리하며 별도 새 스킬로도 등록하려면 노출을 명시적으로 선택합니다.
4. 분류가 있는 데이터는 기본 공격→일반 교체 공격, 변주 스킬→변주, 반주 스킬→반주로 연결합니다. 각 노출 분류가 정확히 하나여야 합니다. 미분류 구버전 데이터는 기존 매핑을 유지합니다. 파일명이나 입력키로 의미를 추론하지 않습니다.
5. **검수 저장**은 미완성 상태도 보존합니다. 다른 대상을 선택할 때 미저장 변경이 있으면 저장·버리기·취소를 선택합니다. 저장 실패 시 변경과 확인창을 유지합니다.
6. **검증**으로 이름·필수 이미지·참조·미검수 후보·ID 충돌을 확인합니다. 오류가 없으면 **최종 반영**에서 변경 요약을 확인한 뒤 반영합니다. 검증 후 편집하면 다시 검증해야 합니다.
7. `npm run characters:validate`로 최종 파일을 검사하고 일반 앱을 새로고침해 확인합니다.

수집 실패는 후보와 오류 목록에 남습니다. 제외한 후보의 다운로드 실패는 유지하되 선택한 초상화·스킬의 필수 검증을 막지는 않습니다. 기존 공개 ID를 보존할 수 없는 손상된 최종 JSON은 반영을 차단합니다.

카드 상단의 이동 손잡이를 같은 목록의 카드에 드래그하거나 앞/뒤 버튼으로 순서를 바꿉니다. 기존 검수 목록과 새 후보 목록을 각각 정리하며, 검수 저장과 재열기·최종 반영 후에도 순서를 유지합니다. 자동 배정·카드 이동 후에는 다시 검증해야 합니다.

## 저장 파일과 충돌 처리

- `.character-sync/runs/<실행 ID>/<공명자 ID>/review.json`: 미완성 검수 상태. Git에서 제외됩니다. 수집 원본 `draft.json`은 수정하지 않습니다.
- 같은 폴더의 `before-publish-<고유 ID>.json`: 반영 전 기존 최종 JSON 원문 백업.
- `src/assets/characters/<ID>/data/<ID>.json`: 앱용 검수 완료 데이터.
- 같은 공명자의 `assets/<내용 hash>.webp`: 실제 디코딩과 hash 확인을 통과한 선택 이미지.

다른 창의 저장 revision, 수집 원본 hash와 기존 최종 파일 hash가 달라지면 덮어쓰지 않습니다. 다른 창에서 저장했다면 대상을 다시 열어 최신 검수를 확인합니다. 수집 원본이나 최종 파일이 외부에서 바뀐 경우 새 수집 실행에서 검수합니다. 충돌한 검수 파일은 보존됩니다.

이미지를 모두 준비하고 재검증한 뒤 JSON 한 파일을 마지막에 교체합니다. 그 전에 실패하면 기존 JSON·참조 이미지는 유지됩니다. 실패 도중 복사된 미사용 새 이미지가 남을 수 있으며 자동 삭제하지 않습니다. JSON 반영은 성공했으나 검수 상태 저장만 실패한 경우 이 사실을 별도로 표시합니다. 여러 검수 서버 프로세스의 동시 반영은 지원하지 않으며 고정 포트로 서버를 하나만 실행합니다.

## 검증과 범위

```sh
npm test
npm run lint
npm run format:check
npm run build
npm run character-review:build
```

저장소 테스트는 임시 폴더의 가상 이미지·JSON으로 최종 반영, 공개 ID 보존, 충돌, 실패 시 기존 파일 보존과 API 경계를 검사합니다. 화면 테스트는 미완성 저장, 미저장 전환, 저장 실패, 검증 후 확인 절차를 검사합니다. 실제 수집 자료의 표시 확인은 의미 검수 완료를 뜻하지 않습니다.

`character-review:build`는 화면 빌드 확인용입니다. 정적 산출물만으로는 파일 API가 동작하지 않으므로 검수에는 개발 서버를 사용합니다. 실제 공명자 의미 검수와 앱 전체 흐름 검증은 [파이프라인 spec](../../specs/2026-10-01-002-character-data-pipeline.md)의 4단계입니다. 웹사이트 공통 UI 아이콘은 사용자 지정 목록을 받은 뒤 별도로 수집합니다.

현재 검수 서버는 `--configLoader bundle`을 명시합니다. Vite 8.3.1은 설정이 참조하는 TypeScript의 확장자 없는 import에 대해 향후 native 로더 호환 경고를 출력하지만 현재 실행·빌드는 통과합니다. 향후 Vite major 업그레이드 때 확인할 항목입니다.
